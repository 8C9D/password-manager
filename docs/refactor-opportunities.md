# Refactor Opportunities Report

_Generated by the repo-cleanup-autopilot skill on 2026-05-28._

## 1. Repository Overview

A local-only desktop password manager built with **Tauri 2** (Rust backend) and
**Angular 21** (TypeScript frontend, standalone components + signals).

- `src-tauri/src/` — Rust backend (~1,750 LOC). Tauri commands grouped under
  `commands/` (vault, entries, categories, generator, settings, clipboard),
  with `crypto/` (Argon2id KDF + AES-256-GCM AEAD), `db/` (rusqlite + bundled
  SQLite, schema in `schema.sql`), `state.rs` (mutex-guarded `AppState` with
  `with_state` / `with_authorized` / `with_unlocked` access helpers), and
  `error.rs` (a single `AppError` enum serialized to a `{kind, message}` wire
  shape).
- `src/app/` — Angular frontend (~2,500 LOC). `core/` holds models, services
  (one per backend domain, plus `tauri-invoke` and `confirm`/`clipboard`/
  `auto-lock`), and the `unlockedGuard`. `features/` holds the standalone
  components. A shared design system lives in the global `src/styles.css`
  (CSS variables + `.btn` family).

## 3. Highest-Value Refactor Opportunities

### Opportunity 1 — De-duplicate the unique-name constraint mapping (categories)

- **Location:** `src-tauri/src/commands/categories.rs`
- **Problem:** `create_category_impl` and `update_category_impl` each inline the
  same `match` arm that maps a SQLite `ConstraintViolation` to
  `AppError::Validation("a category with that name already exists")` and any
  other DB error to `AppError::Database`.
- **Why it matters:** The duplicated error-mapping is easy to let drift (one
  call site could be updated without the other). A single helper makes the
  intent explicit and the call sites smaller.
- **Suggested refactor:** Extract `fn map_category_write_error(e: rusqlite::Error)
  -> AppError` and use `.map_err(map_category_write_error)?` at both call sites.
- **Risk level:** Low
- **Expected benefit:** Removes duplication; both call sites shrink to the
  happy-path logic.
- **Suggested validation:** `cargo test` (covered by `create_rejects_duplicate_name`,
  `update_rejects_duplicate_name`, `update_returns_category_not_found_for_missing_id`).
- **Dependency ordering:** None (independent).
- **Autopilot status:** Implemented

### Opportunity 2 — Resolve clippy `type_complexity` in entries (type alias)

- **Location:** `src-tauri/src/commands/entries.rs` (`encrypt_optional`)
- **Problem:** `encrypt_optional` returns the bare tuple
  `Result<(Option<Vec<u8>>, Option<Vec<u8>>), AppError>`, which clippy flags as
  `type_complexity` — the only lint warning in the crate.
- **Why it matters:** The tuple `(encrypted_bytes, nonce)` has meaning that the
  raw type doesn't convey; a named alias documents it and clears the lint.
- **Suggested refactor:** Introduce `type OptionalCiphertext = (Option<Vec<u8>>,
  Option<Vec<u8>>);` and use it as the return type.
- **Risk level:** Low
- **Expected benefit:** Zero warnings from `cargo clippy`; clearer signature.
- **Suggested validation:** `cargo clippy --all-targets` (warning gone) + `cargo test`.
- **Dependency ordering:** None (independent).
- **Autopilot status:** Implemented

### Opportunity 3 — Remove the dead `last_used_at` read in `get_entry_impl`

- **Location:** `src-tauri/src/commands/entries.rs` (`EntryRow`, `get_entry_impl`)
- **Problem:** `EntryRow.last_used_at` is selected from the DB (`r.get(11)`) but
  never used — `get_entry_impl` always returns `last_used_at: Some(now)` after
  bumping the column. The field carries an explicit `#[allow(dead_code)]`.
- **Why it matters:** Dead reads and `#[allow(dead_code)]` suppressions hide
  intent. Removing them makes the struct match what the code actually consumes.
- **Suggested refactor:** Drop the `last_used_at` field from `EntryRow`, the
  trailing `last_used_at` column from that `SELECT`, and the `r.get(11)` read.
- **Risk level:** Low
- **Expected benefit:** Smaller struct; one fewer selected column; no
  `#[allow(dead_code)]` needed.
- **Suggested validation:** `cargo test` (covered by `get_round_trips_password_and_notes`,
  which asserts `full.last_used_at.is_some()` from the response, not the row) +
  `cargo clippy`.
- **Dependency ordering:** None (independent; same file as Opp 2 but disjoint code).
- **Autopilot status:** Implemented

## 5. Larger Refactors

- **Consolidate duplicated Rust test fixtures** (`locked_state` / `unlocked_state`
  / `fixed_key`) that recur across `entries.rs`, `categories.rs`, `settings.rs`,
  `state.rs`, and `crypto/aead.rs`. Would require a shared `#[cfg(test)]`
  support module and `pub(crate)` exposure. _Not auto-applied_ — see §6.
- **Finish the inline-template/style split.** A prior sweep moved `entry-form`,
  `entry-detail`, `vault-unlock`, and `settings` to external `.html`/`.css`,
  but `category-manage`, `password-generator-panel`, `vault-layout`,
  `entry-list`, `category-sidebar`, `confirm-dialog`, and `entry-empty` still
  inline theirs. _Not auto-applied_ — see §6.

## 6. Things Not Worth Refactoring Yet (or that need a human)

- **`get_entry_impl` swallows DB errors.** The row read uses
  `.query_row(...).ok()` then `.ok_or(AppError::EntryNotFound)?`, which maps a
  genuine database error to "entry not found." The idiomatic fix is rusqlite's
  `OptionalExtension::optional()?`. _Skipped by autopilot_: this changes error
  semantics (a behavior change) in a crypto-adjacent read path and deserves a
  human decision. Recommended for follow-up.
- **Duplicated Rust test fixtures.** The helpers differ slightly (`entries.rs`
  seeds a non-zero `fixed_key`; others use `[0u8; 32]`), and self-contained
  test modules are a defensible status quo. _Skipped_: multi-file, test-only
  churn for modest gain.
- **Auto-lock magic numbers (30 / 86400 / 300).** Duplicated across
  `settings.component.ts`, `settings.component.html` (`min`/`max`),
  `settings.service.ts`, and — authoritatively — the Rust backend
  (`MIN/MAX/DEFAULT_AUTO_LOCK_SECS`). _Skipped_: cannot be unified across the
  TS/HTML/Rust boundary without binding changes; a partial extraction would
  create a second source of truth for marginal benefit.
- **`.btn.danger` defined in three component stylesheets** (`category-manage`,
  `entry-detail.css`, `confirm-dialog`) in two distinct variants (outline vs
  filled). _Skipped_: CSS has no automated coverage and Angular view
  encapsulation makes consolidation risky for visual regressions; needs manual
  visual verification.
- **The `try/catch` + `busy`/`errorMsg`/`formatBackendError` component pattern.**
  Shallow, idiomatic Angular repetition; extracting it would add an abstraction
  without clear benefit.
