## 1. Repository Overview

A local-only desktop password manager built with **Tauri 2** (Rust backend) and
**Angular 21** (TypeScript frontend, standalone components + signals).

- `src-tauri/src/` — Rust backend (~1,750 LOC). Tauri commands grouped under
  `commands/` (vault, entries, categories, generator, settings, clipboard),
  with `crypto/` (Argon2id KDF + AES-256-GCM AEAD), `db/` (rusqlite + bundled
  SQLite, schema in `schema.sql`), `state.rs` (mutex-guarded `AppState` with
  `with_state` / `with_authorized` / `with_unlocked` access helpers), and
  `error.rs` (a single `AppError` enum serialized to a `{kind, message}` wire
  shape).
- `src/app/` — Angular frontend (~2,500 LOC). `core/` holds models, services
  (one per backend domain, plus `tauri-invoke` and `confirm`/`clipboard`/
  `auto-lock`), and the `unlockedGuard`. `features/` holds 11 standalone
  components. A shared design system lives in the global `src/styles.css`
  (CSS variables + `.btn` family).

## 3. Highest-Value Refactor Opportunities

### Opportunity 1 — De-duplicate the unique-name constraint mapping (categories)

- **Location:** `src-tauri/src/commands/categories.rs`
- **Problem:** `create_category_impl` and `update_category_impl` each inlined the
  same `match` mapping a SQLite `ConstraintViolation` to a "name already exists"
  validation error and any other DB error to `AppError::Database`.
- **Why it matters:** Duplicated error-mapping is easy to let drift.
- **Suggested refactor:** Extract `fn map_category_write_error(...) -> AppError`.
- **Risk level:** Low
- **Suggested validation:** `cargo test`.
- **Autopilot status:** Implemented (commit `968f1ae`)

### Opportunity 2 — Resolve clippy `type_complexity` in entries (type alias)

- **Location:** `src-tauri/src/commands/entries.rs` (`encrypt_optional`)
- **Problem:** Returned a bare `Result<(Option<Vec<u8>>, Option<Vec<u8>>), ...>`.
- **Suggested refactor:** Introduce a named `OptionalCiphertext` alias.
- **Risk level:** Low
- **Suggested validation:** `cargo clippy --all-targets` + `cargo test`.
- **Autopilot status:** Implemented (commit `c5a4bd3`)

### Opportunity 3 — Remove the dead `last_used_at` read in `get_entry_impl`

- **Location:** `src-tauri/src/commands/entries.rs`
- **Problem:** `EntryRow.last_used_at` was selected but never used (carried an
  explicit `#[allow(dead_code)]`).
- **Suggested refactor:** Drop the field, the SELECT column, and the read.
- **Risk level:** Low
- **Suggested validation:** `cargo test` + `cargo clippy`.
- **Autopilot status:** Implemented (commit `fdd083d`)

### Opportunity 4 — Fix clippy `io_other_error` in error test (NEW)

- **Location:** `src-tauri/src/error.rs:146` (test module)
- **Problem:** `std::io::Error::new(std::io::ErrorKind::Other, "disk gone")` trips
  clippy's `io_other_error` lint (newly on-by-default in clippy 1.95.0). It is the
  **only** warning the crate now emits.
- **Why it matters:** A clean `cargo clippy` is a meaningful baseline; this lint
  will nag on every run until fixed. The fix is the lint's own suggestion.
- **Suggested refactor:** Use the dedicated constructor:
  `std::io::Error::other("disk gone")`.
- **Risk level:** Low (test-only, mechanical, clippy-suggested).
- **Expected benefit:** `cargo clippy --all-targets` becomes warning-free.
- **Suggested validation:** `cargo clippy --all-targets` (0 warnings) + `cargo test`
  (covered by `database_and_io_errors_serialize_to_opaque_kinds`).
- **Dependency ordering:** None (independent).
- **Autopilot status:** Planned

### Opportunity 5 — Finish the inline-template/style split (per component)

- **Location:** the 7 `features/` components still using inline `template:` /
  `styles:`: `entry-detail/entry-empty`, `category-sidebar`, `entry-list`,
  `confirm-dialog`, `vault-layout`, `password-generator/password-generator-panel`,
  `category-manage`.
- **Problem:** A deliberate, in-progress refactor (commits `876cda4`, `944deaf`,
  `57e5181`, and the entry-form split) moved `entry-form`, `entry-detail`,
  `vault-unlock`, and `settings` to external `.html`/`.css` via
  `templateUrl`/`styleUrl`. The remaining 7 components are inconsistent with that
  established convention.
- **Why it matters:** Consistency and separation of concerns (proper
  HTML/CSS tooling, smaller `.ts` files). Finishing the pattern removes the
  inline/external split that the partial migration created.
- **Suggested refactor:** For each component, move the template literal verbatim
  into `<name>.component.html` and the `styles: [\`…\`]` string verbatim into
  `<name>.component.css`, then reference them with `templateUrl` / `styleUrl`
  (singular — matching the existing convention).
- **Risk level:** Low. The move is **verbatim** (no content change) and fully
  validated by `ng build` (template compilation is strict and would fail on any
  error) plus the Vitest suite. Inline `styles` and external `styleUrl` compile
  identically under Angular view encapsulation, so there is no visual change.
- **Expected benefit:** All 11 feature components use one consistent convention.
- **Suggested validation:** `ng build` + `ng test` after **each** component.
- **Dependency ordering:** None; each component is independent. Done **one at a
  time, one commit each** — i.e. decomposed into small cleanups rather than a
  single large refactor.
- **Autopilot status:** Planned (per-component)

## 6. Things Not Worth Refactoring Yet (or that need a human)

- **`get_entry_impl` swallows DB errors.** The row read uses
  `.query_row(...).ok()` then `.ok_or(AppError::EntryNotFound)?`, mapping a
  genuine DB error to "entry not found." The idiomatic fix is rusqlite's
  `OptionalExtension::optional()?`. _Skipped_: changes error semantics (a
  behavior change) in a crypto-adjacent read path; deserves a human decision.
- **Duplicated Rust test fixtures.** The helpers differ slightly (`entries.rs`
  seeds a non-zero `fixed_key`; others use `[0u8; 32]`), and self-contained test
  modules are a defensible status quo. _Skipped_: multi-file, test-only churn for
  modest gain.
- **Auto-lock magic numbers (30 / 86400 / 300).** Duplicated across
  `settings.component.ts`, `settings.component.html` (`min`/`max`),
  `settings.service.ts`, and — authoritatively — the Rust backend
  (`MIN/MAX/DEFAULT_AUTO_LOCK_SECS`). _Skipped_: cannot be unified across the
  TS/HTML/Rust boundary without binding changes; a partial extraction would
  create a second source of truth.
- **`.btn.danger` defined in three component stylesheets** (`category-manage`
  and `entry-detail.css` use an **outline** variant; `confirm-dialog` uses a
  **filled** variant). _Skipped_: CSS has no automated coverage and Angular view
  encapsulation makes consolidation risky for visual regressions; needs manual
  visual verification. (Note: Opportunity 5 only **moves** these blocks verbatim
  into per-component `.css` files — it does not attempt to consolidate them.)
- **The `try/catch` + `busy`/`errorMsg`/`formatBackendError` component pattern.**
  Shallow, idiomatic Angular repetition; extracting it would add an abstraction
  without clear benefit.
